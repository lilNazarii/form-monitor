# Form Monitor Server v5 — закрытая серверная версия

Этот пакет запускается на Linux-сервере. Не устанавливайте его через прежний Install.cmd и не заменяйте им работающую Windows-версию.

## Подготовлено

- Flask + Gunicorn, HTTPS на входе через Render.
- Регистрация, вход и отдельные данные аккаунтов.
- Google OAuth для Web application с постоянным HTTPS callback.
- Шифрование Gmail-токенов отдельным серверным ключом.
- Chromium без видимого окна. Одновременно выполняется одна проверка на сервере.
- Сохранение расписаний и их восстановление после перезапуска, даже если никто не вошёл в кабинет.
- Постоянная папка /var/data для базы, настроек и отчётов.
- Перенос форм и истории из локальной версии без паролей, почтовых токенов и активных расписаний.

## Что ещё нужно для фактического запуска

1. Рабочее пространство Render и приватный Git-репозиторий с файлами этого пакета в корне. Dockerfile и render.yaml уже подготовлены.
2. Подтверждённый платный тариф и постоянный диск. Конфигурация рассчитана на один экземпляр, 1 CPU / 2 GB RAM (`1c-2g`), Frankfurt, диск 1 GB. Окончательную стоимость нужно проверить в Render перед созданием. Сам пакет ничего не покупает и не размещает.
3. Google OAuth client типа **Web application**. Прежний Desktop client остаётся для Windows.
4. Общедоступная HTTPS-страница с вашей формой. `form-monitor-lab.local` с сервера не открывается. Временный туннель к ноутбуку работает только пока ноутбук включён и не завершает независимый перенос.

## Настройки Render

| Переменная | Значение |
| --- | --- |
| FM_STORAGE_ROOT | /var/data — должен быть подключён постоянный диск |
| FM_PUBLIC_URL | Основной HTTPS-адрес, например https://sentleaf.app; если не задан, используется RENDER_EXTERNAL_URL |
| FM_ENCRYPTION_KEY | 64 случайных шестнадцатеричных символа; хранить отдельно от резервной копии данных |
| FM_SETUP_CODE | Случайный код первого владельца, минимум 24 символа; Blueprint генерирует его |
| FM_ALLOWED_EMAILS | Email владельца и приглашённых тестировщиков, через запятую |
| FM_ALLOWED_FORM_HOSTS | Старые разрешённые домены владельца, через запятую. Новые пользователи подтверждают свой сайт автоматически в мастере подключения; дополнять список для них не нужно |
| GOOGLE_CLIENT_ID | ID клиента Google типа Web application |
| GOOGLE_CLIENT_SECRET | Секрет того же клиента |
| RESEND_API_KEY | Ключ Resend для уведомлений |

При подключении своего домена сначала настройте DNS, дождитесь сертификата Render и добавьте `<FM_PUBLIC_URL>/oauth/google/callback` в Authorized redirect URIs клиента Google. Затем измените FM_PUBLIC_URL и перезапустите сервис. На новом домене потребуется снова войти в аккаунт. Ссылки на главную, кабинет, вход и восстановление пароля на прежнем адресе Render перенаправляются на новый домен; адрес Render определяется по системной переменной RENDER_EXTERNAL_HOSTNAME. Запросы API и OAuth на старом домене отклоняются, параметры URL не пересылаются. Render Subdomain оставьте включённым для работы старых закладок.

Сгенерировать ключ на своём компьютере:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

Введите его непосредственно в Render. Не добавляйте ключи, google_client.json или результаты проверок в Git. Не меняйте FM_ENCRYPTION_KEY после подключения Gmail без процедуры перешифрования: старые токены перестанут читаться.

В Google Cloud задайте Authorized redirect URI в точности:

```text
https://ваш-сервис.onrender.com/oauth/google/callback
```

Scope остаётся `https://www.googleapis.com/auth/gmail.readonly`. В Testing добавьте свои Google-аккаунты в Test users. В этом режиме Gmail refresh token истекает через 7 дней; потребуется повторное подключение. До публичного запуска потребуется отдельная подготовка и проверка OAuth-приложения Google.

После запуска откройте Open workspace, создайте владельца с email из FM_ALLOWED_EMAILS и кодом FM_SETUP_CODE. Затем Connections → Connect Gmail, разрешите доступ, добавьте форму или импортируйте прежние данные и выберите подключённый ящик.

Уведомления идут на email аккаунта. Resend должен разрешать этого получателя; ограничения тестового отправителя сохраняются. Новые реальные письма без запуска проверки не отправляются.

## Перенос прежних форм и истории

### Временная проверка через Local Live Links (v5.1)

Для проверки существующего WordPress без отдельного хостинга добавлена поддержка
HTTP-аутентификации Live Link для аккаунта первого владельца сервера.
Остальные аккаунты не получают эти реквизиты. Логин и пароль передаются только
проверке с точным настроенным доменом; Chromium ограничивает их HTTPS-origin этого
сайта. Они не сохраняются в профиле и не возвращаются интерфейсу.

После обновления `server.py` и `workspace.py` в Render задайте:

| Переменная | Значение |
| --- | --- |
| FM_ALLOWED_FORM_HOSTS | Добавьте точный домен Live Link к существующему списку разрешённых доменов |
| FM_LIVE_LINK_HOST | Тот же домен, например `your-lab.localsite.io`, без `https://` и пути |
| LIVE_LINK_USER | Username из Local → Tools → Live Links |
| LIVE_LINK_PASSWORD | Password из Local → Tools → Live Links |

Домен не должен содержать `*`. Пароль вводите непосредственно в Render, без кавычек.
После сохранения переменных нужен deploy, чтобы процесс получил новые значения.
Local и тестовый сайт должны работать, а компьютер — оставаться включённым и онлайн.
Эта проверка выполняется на Render, но доступность тестового WordPress зависит от ПК.

В кабинете владельца выберите Monitors → Connect a form. Укажите полный HTTPS URL
страницы Contact в Live Link, затем подключённый Gmail, на который WordPress
действительно отправляет письма. Выключите расписание на время ручной проверки.
Запустите одну проверку и проверьте результат, письмо с тем же `MONITOR-…` и отчёт.
Если Local показывает HTML-страницу входа вместо HTTP-аутентификации или форма
использует CAPTCHA, этот вариант требует дополнительной интеграции.

Поддержка проверена автоматическими тестами с имитацией процесса отправки. Это
не подтверждает фактическую доставку письма: её нужно проверить после обновления
работающего сервиса. Ожидание Gmail остаётся 45 секунд.

### Импорт локальной истории

Сначала остановите локальный dashboard.py и текущие проверки. Скопируйте transfer.py из этого пакета в отдельную доступную папку. Выполните на Windows, подставив свой email и путь к transfer.py:

```powershell
.\.venv\Scripts\python.exe C:\путь\к\transfer.py export --root C:\Users\nazar\form-monitor --email ВАШ_EMAIL --archive C:\Users\nazar\Desktop\form-monitor-data.zip
```

Этот архив содержит формы, историю и скриншоты; он может содержать личные данные, поэтому не публикуйте его в репозитории. Пароли и Gmail-токены не включаются.

На сервере сначала создайте аккаунт назначения. Он должен быть без мониторов. Загрузите архив приватно на постоянный диск, остановите проверки, затем в Shell выполните:

```bash
python transfer.py import --root /var/data --email ВАШ_EMAIL --archive /var/data/form-monitor-data.zip
```

После импорта перезапустите сервис. Импортированные расписания приостановлены; каждой форме нужен общедоступный HTTPS URL и новое подключение Google. Старая история остаётся доступна, а изменённая версия настроек требует новой проверки. Не переносите accounts.sqlite3 и зашифрованные Windows-токены как способ переноса аккаунта.

## Проверки и границы этой сборки

Gunicorn также проверен отдельным запуском: сервер отвечает на health и login и корректно останавливается.

Автоматические проверки: HTTPS cookie/CSRF/Host, вход и закрытая регистрация, изоляция данных и скриншотов, шифрование токенов, Google callback другого аккаунта и повтор callback, восстановление расписаний, общий лимит запуска, фильтр адресов и перенос без секретов. Google в этих тестах имитируется, реальные письма не отправляются.

Контейнер Docker и настоящий Google callback должны быть проверены при первом размещении: в среде подготовки Docker отсутствует. Сервер ещё не считается развёрнутым до успешного deploy и одной реальной проверки через доступную форму.

Это закрытая версия для владельца и доверенных тестировщиков. Разрешайте только сайты, которые вы контролируете. Ограничение доменов и публичных IP — дополнительный фильтр, а не полная песочница для произвольных недоверенных сайтов. Для публичного SaaS потребуется отдельная изоляция браузерных заданий и сети, верификация email/восстановление доступа, работа с ограничениями Google и эксплуатационная настройка. Не увеличивайте Gunicorn workers или количество экземпляров: текущие сессии и очередь рассчитаны на один процесс.

Диск нужно контролировать по объёму: автоматическая очистка отчётов пока не включена. Резервное копирование основных данных выполняется автоматически раз в 24 часа; последние семь зашифрованных копий хранятся на том же диске. Владелец может скачать копию в Connections → Server backups. Сохраните скачанный архив вне Render, а ключ шифрования — отдельно. Порядок проверки и восстановления: [BACKUP_RESTORE.md](BACKUP_RESTORE.md). История проверок и скриншоты в эти копии не входят. При аварийном перезапуске незавершённая проверка может быть прервана; сохранённое расписание будет восстановлено.
