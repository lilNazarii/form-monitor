# Резервное копирование Form Monitor

## Что сохраняется

Аккаунты и хеши паролей, настройки форм, расписания, зашифрованные подключения Gmail
и последнее состояние отправленных уведомлений. История проверок, скриншоты,
временные файлы и переменные окружения сервера в копию не входят.

Копия целиком зашифрована существующим `FM_ENCRYPTION_KEY`. Этот ключ нужен для
расшифровки архива и токенов Gmail. Сохраните его отдельно, например в менеджере
паролей. Не меняйте его при переносе на новый сервер. В GitHub и чат ключ не нужен.
Также сохраните конфигурацию Render, включая Google OAuth, Resend и разрешённые
адреса. Архив данных не заменяет конфигурацию сервера.

## На работающем сервере

После установки обновления сервер создаёт копию при первой возможности, затем
каждые 24 часа. Если идёт проверка формы, копирование откладывается и повторяет
попытку через минуту. HTTP-изменения и фоновые проверки исключаются на время
создания согласованной копии. SQLite копируется через штатный backup API.

В `/var/data/backups` хранятся последние семь проверенных архивов. Ограничение
основных данных — 10 MiB; при превышении копирование выдаёт ошибку, старые архивы
сохраняются. Неудача видна владельцу в Connections и в журнале сервера.
`FM_BACKUPS_ENABLED=0` отключает автоматические копии; скачивание остаётся доступным.

Владелец: **Connections → Server backups → Download backup**. Кнопка создаёт
и скачивает архив `.fmbackup` (при повторном нажатии в течение минуты используется
недавний архив). Проверка или отключение Local для этого не требуются.

Храните скачанную копию отдельно от Render. Копии на том же диске помогают после
ошибочного изменения данных, но при потере всего диска нужны скачанный архив
и отдельно сохранённый ключ. Автоматическая выгрузка во внешнее хранилище пока
не настроена. Для первой беты достаточно регулярно скачивать копию владельцем;
перед платным запуском требуется отдельное хранилище с автоматической выгрузкой.

## Проверка восстановления без изменения работающего приложения

После скачивания копии откройте **Render → form-monitor → Shell**. Эти команды
используют ключ из окружения сервера, не выводят его и не отправляют писем:

```bash
cd /app
python - <<'PY'
from pathlib import Path
from datetime import datetime, timezone
from backups import backup_files, read_archive, restore_backup
archives = backup_files(Path('/var/data'))
if not archives:
    raise SystemExit('Сначала скачайте резервную копию через Connections.')
archive = archives[0]
manifest, _ = read_archive(archive)
destination = Path('/tmp') / ('fm-restore-' + datetime.now(timezone.utc).strftime('%Y%m%dT%H%M%S%f'))
restore_backup(archive, destination)
print('BACKUP VERIFIED')
print('Accounts:', manifest['accounts'])
print('RESTORE OK:', destination)
print('Schedules paused. Live data unchanged.')
PY
```

Папка `/tmp` временная: подходит для проверки восстановления. Копии рабочего
приложения остаются в `/var/data/backups`. Не запускайте сервер на тестовой папке.

## Команды для переноса на новый сервер

```bash
python backups.py verify --archive /путь/к/архиву.fmbackup
python backups.py restore --archive /путь/к/архиву.fmbackup --destination /новая/папка
```

Нужен Python с зависимостями проекта и исходный `FM_ENCRYPTION_KEY` в окружении.
Папка назначения должна отсутствовать. Архив проверяется полностью до записи;
существующий каталог никогда не заменяется. Расписания в восстановленной копии
всегда выключены, исходное расписание остаётся в архиве. Google может отозвать
или просрочить токен независимо от сохранности копии — тогда потребуется
повторное подключение Gmail.

Реальное аварийное переключение — отдельная операция: остановите приложение,
сохраните текущие данные, подготовьте постоянный диск нового экземпляра из
проверенной папки, восстановите переменные окружения и права пользователя
`pwuser`, запустите приложение, проверьте вход и Gmail, затем включайте расписания.
Не копируйте восстановленную базу поверх работающего процесса.

## Проверено при разработке

Тест восстановления создаёт отдельный экземпляр приложения: вход прежним паролем,
настройки монитора, расшифровка Gmail-токена и остановленное расписание.
Дополнительно проверяются SQLite WAL, повреждённый архив, неверный ключ,
опасные пути, запрет перезаписи, доступ только владельца, CSRF и ротация.
Google и отправка форм в тестах не вызываются. Проверку реальной серверной копии
следует выполнить командами выше после установки обновления.

Источники: [SQLite backup API в Python](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup),
[постоянные диски Render](https://render.com/docs/disks).
